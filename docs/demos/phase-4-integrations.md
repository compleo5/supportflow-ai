# Phase 4 — Integrations

## What It Does

Connects SupportFlow AI to the real-world tools a support team already uses: Zendesk for ticket management, Slack for escalation alerts, email for outbound responses, and per-customer rate limiting to prevent API cost overruns. Every resolved ticket creates or updates a Zendesk record. Every escalation fires a Slack alert with the full handoff document. The system goes from a demo that logs to the console to one that operates like a real support platform.

## How It Works

### Zendesk Integration (`tools/zendesk.ts`)
- **`create-zendesk-ticket`** — Creates a new ticket with subject, description, requester email, priority (mapped from urgency: critical → urgent, high → high, medium → normal, low → low), and classification/sentiment tags.
- **`update-zendesk-ticket`** — Adds a comment to an existing ticket and updates priority/tags.
- **`search-zendesk-tickets`** — Queries open tickets by requester email. Used at the start of `integrationsStep` to detect if the customer already has an open ticket (reply to existing vs create new).
- **Deduplication logic** — If the customer has an open/pending ticket, the pipeline replies to it; otherwise creates a new one. Prevents ticket spam from repeat emails.

### Slack Integration (`tools/slack.ts`)
- **`send-escalation-alert`** — Fires when `classification === 'escalation'`. Posts to the configured channel with: customer email, urgency level, Zendesk ticket ID, and the full handoff document.
- **`send-slack-notification`** — General-purpose notification for other events (daily digest, KB update alerts).
- **`get-slack-messages`** — Reads recent messages from a channel (used for testing/auditing).

### Email Integration (`tools/email.ts`)
- **`poll-inbox`** — Reads unread emails from the configured Gmail inbox. In production, this runs on a schedule to trigger the pipeline automatically.
- **`send-email`** — Sends outbound emails via the configured provider. Note: in the current integration, email replies are handled by Zendesk's built-in auto-reply on ticket create/update to avoid double-sending.
- **`get-sent-emails`** — Retrieves sent email history for auditing.

### Rate Limiting
- 10 requests per hour per customer email address.
- Checked at the very first step (before pre-filter, before any LLM calls).
- Returns `resetInSeconds` so the calling system can tell the customer when to retry.

### Integrations Step (`support-pipeline.ts: integrationsStep`)
- Runs after the Response Composer, as the final pipeline step.
- Orchestrates Zendesk + Slack in sequence. Failures in either are caught and logged — they do not fail the pipeline, ensuring the response is always stored even if external integrations are unavailable.

## Key Design Decisions

- **Zendesk as source of truth** — All ticket state lives in Zendesk, not in SupportFlow. This means the system can be replaced or upgraded without losing ticket history, and support agents can work directly in Zendesk without needing to learn another tool.
- **Integrations step failures are non-fatal** — A Zendesk outage or Slack rate limit should not prevent the response from being stored and visible in the Review UI. Fail gracefully: log the error, continue the pipeline.
- **Email handled by Zendesk, not directly** — Zendesk automatically emails customers when a ticket is created or a comment is added. Sending separately via Resend would double-send. This avoids duplicating Zendesk's email infrastructure.
- **Rate limiter at step 0** — Placing rate limiting before any LLM calls means an abusive customer burns zero API tokens. The order of operations: rate check → pre-filter → triage → specialist → compose → integrations.

## Test Coverage

- Integration: 11 tests in `rate-limiter.test.ts` — all rate limiting scenarios covered
- Unit: Zendesk, Slack, and email tool schemas validated (tool definitions have correct input/output schemas)
- Manual testing: All four demo scenarios in `demo-walkthrough.md` exercise the integrations step

## PM Takeaway

Integrations are where AI demos become AI products. Connecting to Zendesk means support team leads can see SupportFlow's output in a tool they already review daily — no change management required. Choosing the right integration points (Zendesk as source of truth, Slack for alerts) shows understanding of how support teams actually operate.
